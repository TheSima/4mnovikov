# speedtests — замер скорости интернета

Скрипт скачивает указанный URL несколькими (по умолчанию — параллельными) запросами,
дожидается полного скачивания каждого ответа, вычисляет среднее время запроса,
общий объём скачанных данных и суммарную скорость.

## Синтаксис

```shell
python speed_test.py [url] [-r ЗАПУСКОВ] [-p ПАРАЛЛЕЛИЗМ] [-n ВСЕГО_ЗАПРОСОВ]
```

Все параметры опциональны. `url` — адресный аргумент, идёт первым.

## Параметры

| Параметр | Назначение                                                       | По умолчанию                        |
|----------|------------------------------------------------------------------|-------------------------------------|
| `url`    | Адрес для скачивания                                             | `https://speedtest.selectel.ru/10MB`|
| `-r`     | Количество запусков (rounds)                                     | `1`                                 |
| `-p`     | Параллелизм: сколько запросов параллельно в одном запуске        | `3`                                 |
| `-n`     | Всего запросов в тесте (приоритет над `-r`)                      | не задан                            |

Ограничения:
- Параллелизм в одном запуске не может превышать `32` (защита от исчерпания
  ресурсов). Проверяется по итоговому числу запросов в запуске, поэтому
  ограничение действует и в сценариях, где параллелизм выводится из `-n` и `-r`
  (например, `-n 1000 -r 1` → 1000 параллельных → ошибка).
- На каждый запрос действует таймаут `60` секунд: если сервер не отвечает,
  запрос прерывается с ошибкой.
- Если заданы и `-n`, и `-r`, то `-n` должен быть не меньше `-r`
  (каждый запуск содержит минимум 1 запрос). Иначе — ошибка.

### Как считаются параметры

- **`-n`** — всего запросов. Если задан, имеет приоритет:
  - вместе с `-r` — запусков = `-r`, параллелизм = `⌈-n / -r⌉` (значит `-p` не учитывается);
  - без `-r` — запусков = `⌈-n / -p⌉`.
- **`-r`** — число запусков. Если задан без `-n` — всего запросов = `-r × -p`.
- **`-p`** — параллелизм в одном запуске. Учитывается, если не задан `-n`
  вместе с `-r`.

Без параметров: **один запуск, 3 параллельных запроса** (`-r 1 -p 3`).

## Примеры

```shell
# 2 запуска по 5 параллельных (всего 10)
python speed_test.py -r 2 -n 10

# 3 запуска по 3 параллельных (всего 9)
python speed_test.py -r 3 -p 3

# 10 параллельных запросов, свой адрес
python speed_test.py -p 10 https://speed.cloudflare.com/__down?bytes=10485760
```

## Замечание про параллельные соединения

Для проверки скорости соединения **лучше использовать несколько параллельных
соединений**, а не одно. Причина:

- Современные каналы (Wi-Fi, LTE/5G, волоконно-оптика с QoS) часто ограничивают
  пропускную способность **одного TCP-потока** ниже, чем весь канал.
- Один поток упирается в окно TCP, задержку (RTT), потерю пакетов и ограничения
  коннекшн-трекера на роутере/провайдере.
- Несколько потоков суммарно используют канал ближе к его реальному максимуму —
  именно так работают speedtest.net, fast.com и аналоги.

Поэтому дефолт скрипта — 3 параллельных запроса в одном запуске. Для точной
оценки пропускной способности используйте больше параллелизма, например
`-r 1 -p 10` или `-r 2 -n 30`. Для проверки «скорости одного потока»
(например, под одно скачивание) используйте `-p 1`.
